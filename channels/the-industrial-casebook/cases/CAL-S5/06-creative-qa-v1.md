## Areas
### Central question strength
- **Rating:** PASS
- **Reason:** Within the calibration scope the carried question is "Where was that money going?" (SP-02): specific, answerable from the ledger, reached after a single assumption-setting beat (SP-01) with no stacked context, and it is a real anomaly from the case (TIC-06/07, TIC-09 — no generic rhetorical question). ### Narrative curiosity

### Evidence clarity
- **Rating:** CONCERN
- **Reason:** Golden samples are evidence-honest at the claim level: every VO and on-screen claim I checked maps to a VERIFIED ledger row; unsupported sentences are cut; no totals, quotes or invented layouts appear; `DIAGRAM · NOT TO SCALE` marks own drawings; the gap stays unscaled because GAO gives no subsidy figure; the operators' line is attributed to NPS without on-screen quote text. No item rises to a HARD BLOCKER because nothing false is placed on screen in a golden sample and anti-references are internal. But several items must be corrected or specified before the plan can be ACTIVE:
  1. **Crane: the cut reason misstates the ledger.** The cut list and SP-05 say the plural "Heavy cranes" is unsupported because "C-31 records one 75-ton portal crane". Ledger **E-11** (GAO s.15, read from the page on 2026-10-10) records a **75-ton gantry crane** and, inside the maintenance building, a **75-ton bridge crane**; the P3 handoff §2 note also says "iki adet 75 ton vinç → 'heavy cranes' doğru". Cutting the sentence is conservative and allowed (removing a claim never breaks truth), but the written justification and the SP-05 claim ("one 75-ton portal crane") are inaccurate records. In addition, the on-screen label `75-TON PORTAL CRANE` is sourced to `GAO · p.15` but uses the Turkish ledger's translation ("portal vinç"); GAO's own term per E-11 is "gantry crane". The same error sits in the binding audit table (`calibration/02-golden-motion-and-anti-reference.md` §Kanıt denetimi: "C-31 tek 75 t portal vinç"), so the producer should correct both records.
  2. **SP-01 map extent vs C-44.** The regions fill on "a quiet Atlantic map", but C-44 includes **two voyages to the Far East**, which an Atlantic map cannot show. Either the map extent must include the Far East region or the plan must state how that count is shown without misplacing it.
  3. **Archive integrity of V-05 in SP-01 / SP-03.** The 2.5D lateral move from the bridge to the ship and the "whole isolated hull" both require pixels that may not exist in the photograph (areas behind the bridge or other occlusions). The plan says no object is displaced, but does not say how disoccluded areas are handled. It must state that no hull/ship detail is fabricated (e.g., limit parallax so no invented ship detail becomes visible; any fill restricted to neutral sky/water; isolation does not complete occluded hull parts), consistent with TIC-16/TIC-17 and canon `05` §4.
  4. **SP-05 site-plan reading.** The component sheet is drawn on a ground plate that lands at the Galveston map position, with all components arranged around one berth. Ledger E-11 forbids a site plan (GAO gives no layout). `NOT TO SCALE` does not say "not a layout". The plan should state how the sheet is visibly separated from geography before the components draw (or label it so that it cannot be read as an arrangement).
  5. **SP-09 gap/fill scale.** SP-02 defines the gap as an open, unscaled bracket; SP-09 fills it "largely" with the three blocks. For that fill to be honest the gap's width must be defined as ≈$2M (C-04) on the same scale as the blocks (C-08–C-10, total per C-06/C-07), with the remainder unlabelled. The plan should state this so Strong PC does not improvise a ratio.
  6. **J40 identity is not traceable in the package.** SP-07 / SP-09 put `WESTINGHOUSE J40` on screen and describe an "archival test-stand frame"; the rights ledger proves rights for NASA GRC-1951-C-28738 but no evidence row in the inputs establishes what the photo shows. The plan should cite where the identity (and test-stand context) is verified (e.g., the NASA catalogue caption in the rights-proof capture). The "compressor-stage tick marks" motif must not imply an actual stage count (the calibration brief calls it an identity motif, not a technical claim).
  7. **Attribution delivery.** V-05 and V-90 are CLEAR_WITH_ATTRIBUTION. SP-01 shows `AEC / NATIONAL ARCHIVES · 1962`, but SP-03, SP-07, SP-09, SP-10 and SP-13 show these images with UI "number and title only" or anti-reference tags. The plan should state where the attribution goes for these clips (e.g., a credit line per clip in the preview package).
  8. **Anti-reference honesty (internal, but `02` says anti-references still follow evidence and rights rules).** SP-10's "MOST RELIABLE SHIP" card turns an NPS-attributed operator statement (C-36 / Q-06) into an unattributed on-screen assertion; add the `NPS` mark (the failure demonstrated is the card, not missing attribution). SP-11's dossier card "about 2 million a year" drops the C-04 baseline that the ledger guardrail requires ("always relative to the subsidy paid to conventional ships"; D-REJ-3); and its "timestamp and coordinate decoration" must not be invented data that looks factual (use non-informational placeholders or real ledger values such as the report date).
  9. **Asset status for anti-reference graphics.** SP-10–SP-14 use text cards, a dossier card, bouncing icons, a spinning gear, a bullet slide, a "stock lower-third template", a generic worker icon, a red button, a bell and a hand cursor. None has an asset row or status (pipeline §2b: every asset carries `READY` / `TO_PRODUCE` / …; lint rejects undeclared status). Declare them as own `TO_PRODUCE` rows or as built-in software presets/templates, and confirm no third-party stock icon/template is used.
